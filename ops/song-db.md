# 곡 DB 및 크롤링

## 곡 데이터 구조 (현재)

```
곡 (Song)
├── 제목
├── 키 (복수, JSON 배열) ["A", "G", "Bb"]
├── 가사 / 송폼 (텍스트, [Verse]/[Chorus] 구분)
├── 레퍼런스 (1:N)
│    ├── 유튜브 URL + 영상 ID
│    ├── 영상 제목
│    ├── 썸네일
│    ├── 키 (해당 버전)
│    ├── 신뢰도 (HIGH/MEDIUM/LOW, 채널 기반)
│    ├── 출처 (CRAWL/MANUAL)
│    └── 연결된 채널
└── 악보 (1:N)
     ├── 파일 URL
     ├── 파일 타입 (PDF/IMAGE)
     ├── 연결된 레퍼런스 (어떤 편곡 기준)
     └── 업로드자
```

## 같은 곡, 여러 레퍼런스

핵심: 같은 곡이라도 사역팀마다 편곡/키가 다름.
- 마커스 버전 (키: G)
- 어노인팅 버전 (키: A)
- 레퍼런스 품질은 사역팀 신뢰도로 판단

## 크롤링 설계 (현재 구현)

### 파이프라인
```
1. 관리자가 채널 URL 등록 → @handle에서 UC... 자동 변환
2. 크롤링 실행 (수동 트리거)
3. playlistItems API로 채널 업로드 영상 수집 (최대 250개)
4. videos API로 duration 확인
5. 필터링:
   - 20분 초과 → 무시
   - 예배실황/연주/inst/MR/반주/드럼캠 등 → 무시
6. 제목 파싱 → 곡 매칭
   - DB에 같은 곡 있음 → 레퍼런스 추가
   - 없음 → 검증 큐에 등록
7. 검증 큐에서 관리자가 확인:
   - 유사곡 후보 자동 표시
   - [이 곡에 추가] → 기존 곡에 레퍼런스 매칭
   - [새 곡으로 등록] → 새 곡 생성 + 레퍼런스
   - [거부] → 무시
```

### 크롤링 우선 사역팀
- 마커스워십, 어노인팅, 아이자야씩스티원, 위러브
- 잔치공동체, 피아워십, 기프티드

### 필터링 키워드
- 제외: inst, instrumental, 연주, MR, 반주, AR, 드럼캠, 베이스캠, 기타캠, making, shorts, teaser, interview
- 제외: 예배 실황, 주일예배, 설교, sermon

### 자동화 로드맵
```
현재 (MVP)              → 추후 자동화
───────────────────────────────────
관리자가 채널 등록        → 인기 채널 자동 추천
크롤링 수동 실행         → 주기적 자동 크롤링 (cron)
검증 큐 수동 승인        → AI 자동 매칭 (유사도 기반)
가사 수동 입력           → 유튜브 자막 자동 추출
악보 수동 업로드         → AI 채보 자동 생성
```
