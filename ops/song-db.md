# 곡 DB 및 크롤링

## 곡 데이터 구조

```
곡 (Song)
├── 제목
├── 원곡자 / 작곡자 (알 수 있는 경우)
├── 가사
├── 기본 키
└── 레퍼런스 (복수)
     ├── 유튜브 URL
     ├── 사역팀 이름
     ├── 키 (해당 버전의 키)
     ├── 썸네일
     └── 신뢰도 (사역팀 등급 기반)

곡 — 악보 (복수)
     ├── 파일 (PDF / 이미지)
     ├── 연결된 레퍼런스 (어떤 편곡 기준인지)
     └── 업로드자
```

## 같은 곡, 여러 레퍼런스

핵심 문제: 같은 곡이라도 사역팀마다 편곡/키가 다름.

```
예) "주만 바라볼찌라"
├── 마커스 버전 (키: G, 유튜브 링크)
├── 어노인팅 버전 (키: A, 유튜브 링크)
├── 무명 커버 (키: G, 유튜브 링크) → 신뢰도 낮음
```

레퍼런스 품질은 **사역팀 신뢰도**로 판단:
- 등록된 사역팀 채널 = 신뢰도 높음
- 미등록 채널 = 신뢰도 낮음 / 수동 검증 필요

## 크롤링 설계

### 원칙
- 관리자 화면에서 크롤링 대상 채널을 등록/관리
- 모든 크롤링 동작은 API로 제어 가능 (추후 자동화 대비)
- 수집 → 정규화 → 중복 체크 → DB 저장

### 크롤링 대상
- **유튜브 채널**: 관리자가 사역팀 채널 URL을 등록
- **수집 정보**: 영상 제목, URL, 썸네일, 설명(가사 추출용)

### 크롤링 파이프라인

```
1. 채널 목록 (관리자 등록)
   ↓
2. 유튜브 채널 영상 목록 수집
   ↓
3. 영상 정보 파싱
   - 제목에서 곡 제목 추출
   - 설명에서 가사/키 추출 시도
   ↓
4. 곡 매칭 (기존 DB에 같은 곡 있는지)
   - 있으면 → 레퍼런스 추가
   - 없으면 → 새 곡으로 등록
   ↓
5. 관리자 검증 큐 (자동 등록이 애매한 경우)
```

### 자동화 로드맵

```
수동 단계 (MVP)              → 자동화 (추후)
──────────────────────────────────────────────
관리자가 채널 등록             → 인기 채널 자동 탐색
관리자가 곡 매칭 확인          → AI 곡 제목 매칭
관리자가 가사 입력/수정        → 자동 가사 추출
관리자가 키 확인               → 오디오 분석 키 감지
관리자가 악보 업로드           → AI 채보/악보 생성
```

### 사역팀 채널 관리

관리자 화면에서:
- 채널 추가 (유튜브 채널 URL + 사역팀 이름)
- 채널 활성화/비활성화
- 크롤링 주기 설정
- 수집 상태 확인 (마지막 크롤링 시각, 수집 건수 등)
