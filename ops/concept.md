# 서비스 개념

## 한 줄 요약

찬양팀 인도자가 콘티를 짤 때, 곡 검색부터 레퍼런스 확인까지 한 곳에서 해결하는 서비스.

## 문제 인식

현재 찬양팀 운영 (네이버 밴드 등):
- 콘티를 짤 때마다 유튜브에서 곡 레퍼런스를 직접 검색해야 함
- 같은 곡이라도 여러 버전이 있고, 신뢰할 수 있는 사역팀 버전을 찾아야 함
- 곡의 키, 가사, 악보가 흩어져 있어 매번 다시 찾아야 함
- 이전에 했던 곡의 레퍼런스를 다시 찾는 반복 작업

## 핵심 가치

- **콘티 작성이 핵심** — 곡 검색 → 키 설정(키업 포함) → 콘티 완성, 한 화면에서
- **곡 레퍼런스 통합** — 곡 하나에 유튜브 레퍼런스, 키, 가사가 한 곳에
- **신뢰할 수 있는 레퍼런스** — 검증된 사역팀의 영상을 우선 제공
- **콘티 공유** — 텍스트 복사(카톡/밴드) 또는 링크 공유로 팀원에게 전달
- **자동 수집** — 크롤링 봇이 곡 데이터를 지속적으로 수집/업데이트

## 대상 사용자

- **1차**: 교회 찬양팀 인도자 (콘티 작성자)
- **2차**: 찬양팀 멤버 (콘티 확인, 레퍼런스 열람, 사역 배정 확인)
- **관리자**: 곡 DB 품질 관리, 크롤링 운영, 유저 등록 곡 정제

## 사용 환경

- 웹 (모바일/태블릿/데스크톱)
- 네이티브 앱은 추후 필요시 (악보 펜슬 메모, 푸시 알림 등)

## 기존 서비스 대비 차별점

네이버 밴드, 카톡 단톡방 등 범용 도구 대비:
- 곡 단위로 레퍼런스가 정리되어 있음
- 크롤링으로 곡 DB가 자동으로 쌓임
- 콘티 작성에 특화된 UX (키업 표시, 곡 검색 → 즉시 추가)
- 콘티를 텍스트/링크로 쉽게 공유 (사역팀 배정 포함)

## 악보 전략

- 현재: 악보 파일 업로드 X → 외부 링크(구글 드라이브 등) 등록
- 이유: 악보 호스팅은 인프라 복잡도 대비 핵심 가치가 아님
- 대신: 콘티 공유를 통해 팀원이 이 서비스를 방문하는 이유를 만듦
