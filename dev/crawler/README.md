# 크롤링 봇 설계

유튜브에서 CCM/찬양곡 데이터를 자동 수집하는 봇.

## 설계 원칙

- API를 통해 DB에 접근 (직접 DB 접근 X)
- 관리자 화면에서 수동 실행 가능, 추후 자동 스케줄링
- 채널 단위로 크롤링 (관리자가 채널 등록)

## 크롤링 파이프라인

```
1. 채널 목록 조회 (GET /api/admin/channels)
   ↓
2. 유튜브 채널의 영상 목록 수집
   - YouTube Data API 또는 yt-dlp 활용
   - 마지막 크롤링 이후 신규 영상만
   ↓
3. 영상 정보 파싱
   - 제목에서 곡 제목 추출 (정규식 + 패턴 매칭)
   - 설명에서 가사/키 추출 시도
   ↓
4. 곡 매칭
   - 기존 DB에 같은 곡 있는지 검색 (제목 유사도)
   - 확실한 매칭 → 자동으로 레퍼런스 추가
   - 불확실 → 검증 큐에 등록
   ↓
5. 결과 저장
   - 매칭된 곡에 레퍼런스 추가 (POST /api/songs/:id/references)
   - 새 곡이면 곡 등록 (POST /api/songs)
   - 불확실하면 검증 큐 (review_queue 테이블)
   ↓
6. 크롤링 로그 기록
```

## 곡 제목 파싱 전략

유튜브 영상 제목 예시:
```
"주만 바라볼찌라 | 마커스워십 | Keys: G"
"[마커스 4집] 주만 바라볼찌라 (Official)"
"주만 바라볼찌라 - 2024 마커스워십 라이브"
```

파싱 접근:
- 구분자 기반 분리 (|, -, [])
- 사역팀 이름 제거
- 부가 텍스트 제거 (Official, Live, MV, lyrics 등)
- 키 정보 추출 (Keys:, Key:, 패턴)

## 유튜브 데이터 수집 방법

| 방법 | 장점 | 단점 |
|------|------|------|
| YouTube Data API v3 | 공식, 안정적 | 일일 할당량 제한 (10,000 units) |
| yt-dlp | 할당량 없음 | 비공식, 차단 위험 |

MVP에서는 YouTube Data API 사용 권장 (안정성 우선).

## 자동화 단계

```
MVP:    관리자가 수동 실행 (POST /api/admin/crawl/:channel_id)
Phase2: 주기적 자동 실행 (cron job / 스케줄러)
Phase3: 신규 채널 자동 탐색, AI 곡 매칭
```
